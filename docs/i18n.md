# Internationalization

LanternDock uses i18next with bundled translation resources and a small shared
`t()` wrapper. It supports English (`en`) and Simplified Chinese (`zh-CN`).
Chinese browser variants, including `zh-TW` and `zh-HK`, currently use the
Simplified Chinese catalog. Other unsupported languages fall back to English.
There is no language picker, cookie or saved language preference.

## Browser

`shared/i18n.js` selects the first supported entry in `navigator.languages`.
It uses `navigator.language` only when that list is missing or empty; if no
supported language is found, it uses English. This choice stays fixed
for the page load. Reload after changing browser language settings.

Import `t` and, when formatting values, `locale` from `shared/i18n.js`:

```js
import { t, locale } from "../../shared/i18n.js";
t("library.previewNamed", { name: file.name });
new Intl.DateTimeFormat(locale).format(date);
```

Resources live in `locales/en/` and `locales/zh-CN/`, grouped by namespace:
`app`, `library`, `account`, `core`, `server`, and `demo`. The first dot selects
the namespace; subsequent dots are part of a flat key. Add matching keys and
`{{parameter}}` names in both languages. English count messages use i18next's
`_one` / `_other` forms, with a numeric `count`. Missing translated entries fall
back to English. Use complete sentences rather than concatenating fragments.

Components pass translated strings as ordinary Preact text/attribute values.
The wrapper does not HTML-escape interpolation a second time. Do not inject its
output as raw HTML. User filenames, folder names, identities, backend names and
saved upload-link titles remain user data, never translation keys.

Document language, title and description are set before rendering. Date, album
headings, numbers and collation use the chosen locale. Album grouping still uses
local calendar days, modification times, and explicit years outside the current
year. Demo files are localized separately from real file data. Element selectors,
state values, routing and error classification use stable IDs/codes, not copy.

## Server and asynchronous work

The browser sends its selected locale in `Accept-Language` for app API, direct
HTTP, WebTransport-encapsulated HTTP and XHR upload requests. The JavaScript
Worker creates a request-scoped translator from `detectRequestLanguage()`;
never call a global `changeLanguage()` in server code. Quality weights and
header order select supported languages. Missing or unsupported language falls
back to English. Localized responses declare `Content-Language` and vary on
`Accept-Language`; language-neutral discovery/JWKS keep their caching behavior.

The Go NAS has an embedded equivalent catalog in
`server/internal/i18n/locales/`. Its request-local translator resolves fault keys
only when writing an HTTP error. Protocol error codes, status codes, OAuth ASCII
diagnostics and authentication behavior are unchanged. Internal logs and CLI
diagnostics remain English. A new CLI link's default title is English and then
stored as normal data. Existing saved/custom names are not rewritten.

An unspecified backend name is translated per request. Setup omits that default
from new configuration and clears an old override when the name field is cleared.
Explicit existing or edited names remain custom, even if their text happens to
equal the translated default. This prevents automatic localization from changing
a configured name or persisting the current browser language accidentally.

## Checks

- `npm run check`: JavaScript syntax and production build.
- `npm test`: explicit Chinese regression fixtures plus bilingual negotiation,
  interpolation, pluralization, formatting, error and async-isolation tests.
  Catalog keys/placeholders and literal application keys are checked; application
  JavaScript/JSX must not contain Chinese copy outside the catalogs.
- `npm run test:browser`: existing Chinese flows and focused isolated English,
  Chinese and fallback contexts. Locale fixtures are explicit, not host-dependent.
- In `server/`, run `go test -race ./...` and `go vet ./...` for NAS coverage.

Application translations do not translate upstream service messages, browser/OS
errors, user content or technical protocol identifiers. Browser UI and Go tests
must be run on an executor with the corresponding browser and Go toolchain.
