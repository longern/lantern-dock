# Interface conventions

LanternDock keeps its Preact components and restrained purple palette. Shared behavior and visual tokens follow the same principles used by mature component libraries: consistent transitions, accessible modal lifecycles, predictable controls and concise copy. Reference: Material UI [dialogs](https://mui.com/material-ui/react-dialog/) and [transitions](https://mui.com/material-ui/customization/transitions/).

Mobile has no sidebar or hamburger trigger; category shortcuts live on Home.                                                          |

## Maintaining the interface

- Define palette, radius and motion values in `src/styles/base.css`. Overlay animations belong in `src/styles/overlays.css`.
- Use `Dialog` rather than directly unmounting a modal. Set `open` false on dismissal, and remove ephemeral content in `onExited`. Cancel exit cleanup if the same surface reopens. Full-screen mobile subpages use `PageDialog`: a shared slide-in/out surface and fading backdrop, a 60 px app bar plus the top safe area, a centered regular-weight title, 48 px icon targets, 24 px icons and explicit edge compensation. Album and Favorites share this shell; desktop layouts remain standalone pages.
- Keep surface and backdrop mounted for the same exit duration. A `hidden` scrim cannot animate out.
- Do not mix the file service's credentials with account login. Connection help may describe protocol requirements; normal file browsing should not require protocol knowledge.
- Me uses the site session for account information, displayed directly on the page without a card or visible Me heading. Confirmed signed-out sessions show one backgroundless Guest icon-and-text button, without a separate sign-in action or explanatory copy. It opens a native sign-in dialog; only its explicit login action starts the existing identity flow. Dismissal, navigation or resizing cancels pending login before the exit animation, so a late response cannot redirect a newer page. Preserve the allowlisted return-to-Me hint only after successful redirect. Confirmed signed-in sessions use the same backgroundless avatar-and-identity treatment as a single link to account details, without a separate Account details action or Signed in label. Preserve real name/email fields and use My account when both are missing. Loading and unavailable states remain distinct; do not invent account names, avatars or permissions. Keep account information out of local storage. Favorites and connection settings remain usable without signing in.
- Dialogs, popover menus and the Me action group have no outer border. Retain internal separators, input boundaries and visible keyboard focus outlines.
- Use full-width list buttons with icons and chevrons for Me actions. The unpadded outer group owns the rounded clipping; rows have no separate corner styling. Keep keyboard focus inside the clipped rows. Support long account names, narrow screens, visible focus and bottom safe areas. Reuse the existing favorites records and connection settings rather than creating separate copies.
- Favorites has its own route. A mobile native dialog contains the list, while desktop renders a subpage. Its mobile toolbar is 60 px high, plus the top safe-area inset, with a 48 px Back button offset by a -12 px left margin and a centered 16 px regular-weight title. Desktop heading styles stay separate. Back/Forward, direct visits, repeated opening and breakpoint changes must not leave hidden modals or duplicate file-browser IDs. Nested previews dismiss independently; removing the last favorite must leave a usable focus target.
- Ordinary file lists and Favorites use one three-dot menu at the far right of their own header for sort and list/grid choices, with a 48 px target and -12 px right margin. LibraryApp composes the declarative actions slots of Topbar and Favorites from shared listing preferences; headers do not own listing state and child pages do not imperatively replace header controls. This keeps the header's Recent/Album eligibility aligned with the list without sorting entries twice. Menus use checked items, keyboard navigation and local Escape dismissal. A manual popover keeps the popup in its owning dialog's DOM while avoiding transformed or scrolling ancestors in supported browsers. Keep the Files, Home fallback and Favorites sort preferences separate, and preserve the shared list/grid preference when visiting Recent or Album.
- Three-dot menus scale and fade from the anchor position: 180 ms entry and 120 ms exit. Position an unanimated shell from the actual trigger/viewport geometry and animate only its inner surface, so measuring a partially scaled menu cannot move its anchor. Keep the popover present through exit, but immediately disable its input, make it inert and restore focus. Interrupted entry/exit starts from its current visual state; stale completion handlers cannot close a reopened menu. Reduced motion removes the delay. Keep fallback positioning and cleanup correct inside an animated Favorites dialog.
- Share Worker identity through the root session provider and keep lazy NAS authorization separate. Administration appears between My favorites and Settings after a matching NAS identity reports the local administrator role. An older NAS without management capabilities keeps this entry so administrators can open the upgrade guidance; management controls and requests still require explicit capabilities. Direct routes must still show distinct loading, signed-out, unsupported, forbidden and connection/error states. NAS authorization is enforced on each API operation, never by hiding the link.
- Management dialogs use the shared modal lifecycle and translations. Creating a link reveals its secret only in that dialog; closing or leaving the page clears it. Never put link secrets in ordinary list state, browser storage or history. Require explicit confirmation for revocation and explain that completed uploads remain private and available. Do not automatically retry an uncertain create request. Metadata requests have a bounded deadline so an unresponsive network cannot permanently lock the dialog; a timed-out creation remains uncertain until the administrator checks the list.
- Normal file collections use `ul` with `li.file-item` entries in both list and grid views. Each entry has one primary file button with phrasing content; favorite, copy and download actions live in the selection toolbar rather than row-end icon buttons. List view inserts decorative `li > hr` dividers only between entries; dividers and loading placeholders stay out of the accessible item count. On mobile, list row backgrounds fill the viewport; rows own the content gutters, while toolbars, dividers and ordinary grids retain their insets. Do not use negative margins to extend highlights. Reset native list spacing, retain visible keyboard focus, and use FileItem/file-item naming throughout the shared renderer, album styling and tests.
- File selection is local to the current backend, page, directory and search/type filter. Refresh prunes resources that disappear; changing sort or view keeps selected paths. Album ranges and Select all use the displayed chronological media set, excluding hidden paired motion videos. A 450 ms touch hold enters selection; moving more than 10 px, scrolling, cancellation, multiple pointers or releasing early cancels the pending hold. Suppress the release click after a successful hold. In touch selection, taps toggle files and folders, bottom tabs disappear, and a safe-area-aware floating toolbar offers Select all, Download, Favorites and Copy links. It is a manual popover owned by the current file browser, including inside native Favorites/Album dialogs. Mouse selection never opens that panel. Arrow keys move focus through the actual grid rows, Shift extends ranges, Ctrl/Command+A selects all, Ctrl/Command+C copies portal links, Space toggles and Enter opens. Escape exits selection and restores file focus before a containing dialog can close. Batch favorite changes read and save once, with one notification; copying shares portal URLs without NAS credentials.
- Use concise inline guidance and actionable empty states. Keep deployment instructions and identifiers in setup or expandable details.
- Home category cards appear only on Home. Documents include text, PDF and Office formats; books include EPUB, MOBI and other ebook formats. Categories do not enable new preview formats or recursively scan directories.
- Home always renders a search field. Mobile Files shows “Files” in the header and a search button immediately before the options menu, with 4 px between header controls. Tapping search replaces the breadcrumbs with a 36 px search field in the same 40 px mobile tools row and focuses it during the tap, allowing the mobile keyboard to open without moving the file list. Closing restores the breadcrumbs in that row. The header search icon becomes Close; closing or pressing Escape in the search header clears the query, collapses the field and returns focus to the search button. The inline clear button keeps search open, and losing focus or dismissing the keyboard does not close it. A nonempty URL query keeps the field visible after reload without stealing focus. Navigating to another destination, folder or category clears the query and collapses Files search. The topbar has no settings or account button; account access remains in the desktop sidebar and mobile Me page, and connection settings live in the desktop sidebar, mobile Me page and connection-error recovery. Closing settings returns focus to its opener when available, or to the sidebar settings/mobile Me tab after a breakpoint change.
- Recent files come from the current backend's browser-local visit history (up to 30 previewed/downloaded files), not server modification times. Home starts with the recent heading and loading placeholders until the backend namespace and history are known. Only a successful empty-history read falls back to root files; unreadable or corrupt records show a retryable error instead. Recent always uses list layout, sorted by latest visit, without toolbar controls; the empty-history directory fallback keeps its options menu. Visits persist immediately, but the displayed Home records remain unchanged until the preview's actual entry animations finish. An interrupted opening releases the snapshot after dismissal; replacing or reopening a preview cannot release a newer snapshot. Reduced motion has no artificial entry delay. Choose the recent/root source before searching so unmatched recent searches do not silently fall back to other files. The mobile Home card keeps edge-to-edge list rows and flex growth, with an inset recent heading, never negative margins to cancel padding. Home has no divider between search and the category cards.
- The album shortcut includes images and videos in one timeline grouped by WebDAV file modification date, newest first. The separate image and video type filters remain type-specific. Do not add a sorting-explanation caption to the album heading. Groups use the browser's local calendar day and label today/yesterday only within the current year; every other year is explicit, including yesterday across New Year, and missing/invalid dates stay in a final “日期未知” group. These are not EXIF capture dates and do not imply location metadata. Square cover-cropped thumbnails have a 4 px gap, with four edge-to-edge columns on mobile. Tiles have no border, filename, metadata or favorite overlay; video posters have a small play indicator and open the shared player in the album viewer. Each tile remains a named keyboard-accessible button. Album previews use react-photo-view through Preact compatibility in a native modal dialog, with chronological photo/video paging, zoom, favorites, download and expandable file details. Ordinary file previews retain their existing panel. Loading or unavailable thumbnails use a neutral image/video placeholder, without automatically downloading full-size originals or playing videos in the grid. Album chronology is fixed and does not change the user's list/grid or sort preferences for other files.
- Album opening animates from the actual cover-cropped thumbnail without shifting the grid. A viewer-owned thumbnail stays opaque while the current 1600 px preview loads and decodes; the sharp image fades over it for 180 ms after entry, then the low layer is removed. Cached sharp previews skip the fade. A failed sharp request retains the thumbnail and download action. Only adjacent media remain mounted, and only the current page requests a sharp image or creates a video player. Moving away or closing cancels requests, synchronously stops the player and releases viewer Blob URLs. The unified History router records the file URL, replaces it while paging and lets Back dismiss one preview entry; Escape, focus containment/return and reduced-motion dismissal use the native dialog lifecycle. Desktop retains pager buttons and keyboard navigation; mobile omits zoom buttons, hides pager buttons and uses pinch zoom and swipe gestures. Video controls keep their own seek and volume keys rather than changing slides.
- Verify keyboard dismissal, background inertness, focus restoration, reduced motion, narrow layouts and content overflow when changing an overlay.

`test/browser/interactions.spec.mjs`, `menu-motion.spec.mjs`, `session-provider.spec.mjs` and `admin.spec.mjs` cover these interaction contracts alongside the file-browser and setup suites. The admin UI suite uses an explicit identity fixture; it does not substitute for real protocol/bridge integration tests. Real bridge tests validate preview, download, inbox and identity flows against the production frontend. Chromium mobile viewports do not replace physical Safari/iOS or Android device testing.

Directories, previews and subpages use [shareable page URLs](routing.md); the router owns navigation history and overlays retain their animation/focus lifecycle.

- Selected files download sequentially without an archive. A multi-file action requests one writable directory within the click gesture when supported, streams files directly and renames name collisions. Otherwise each file becomes a separate browser download, subject to its automatic-download permission. The fallback holds at most 256 MiB per batch, including issued Blob URLs; oversized selections must be split. Folder selections disable Download instead of silently skipping them. A touch download exits selection and shows the unified transfer summary, including the current file and batch index. Cancellation stops the current stream and every remaining file; completed files remain, while a newly created incomplete directory entry is removed. History is written once for completed files after the queue settles.

## Transfer center

- Home’s top-right transfer button opens a 420 px non-modal window at the desktop bottom right, or a native full-screen mobile dialog that slides in from the right. Downloads automatically expand the desktop window without taking focus; mobile starts with a compact summary. Collapsing either surface keeps the batch running. The summary opens the same task list, replacing the old standalone download panel; administrator inbox downloads reuse this component too.
- Queued, choosing-destination, downloading, saved, handed-to-browser, cancelled and failed states reflect actual requests and file writes. Browser handoff does not claim the browser has saved the file. Cancellation stops the current batch and its remaining queue. Failed or cancelled files can be retried individually once the batch settles, using a new user gesture for any native destination picker. Clearing finished entries preserves running/queued work.
- Retain at most 100 finished entries in memory for the current file-service connection. Reloading, leaving the library/admin workspace, or replacing its connection discards that history and stops active requests; there is no background or reload-resume promise. Only completed files enter recent-file records.
- Mobile opening adds a same-URL History entry so Back closes only the transfer dialog; Forward reopens it. A nested preview retains its own return path. Desktop stays non-modal with local Escape dismissal and no backdrop; mobile inherits focus containment, restoration, safe-area padding, exit animation and reduced motion from PageDialog.

## Album views

- Album and the desktop Images filter share the file menu’s three-dot trigger, anchored grow/fade transition and keyboard behavior. The menu labels its view group “视图”, with “按日期分组” and “连续排列”, followed by a separate “刷新” action. Refresh is disabled during a listing request and skipped by keyboard navigation; Escape dismisses the menu without dismissing the mobile album page.
- Date grouping remains the default. Continuous layout uses the same newest-first photo/video order, live-photo pairing and square thumbnails, without date headings or gaps between date groups. Selection, the viewer’s paging order and thumbnail origins use that same media set. The album view is retained while navigating within the library and remains independent of the ordinary file list/grid preference.

## Responsive breakpoints

The canonical definition is `src/lib/breakpoints.js`, using MUI’s defaults: xs 0, sm 600, md 900, lg 1200 and xl 1536 px. `up` is inclusive and `down` uses MUI’s 0.05 px exclusive upper-bound step. These names describe available space, not input hardware. Pointer events continue to decide mouse selection versus touch long-press.

| Threshold    | Responsibility                                                                                                                                                                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| sm / 600 px  | Phone density: stacked setup/account/admin forms, two-column file cards, compact file metadata and four-column album thumbnails. From sm to md, albums have six columns and file lists retain metadata columns.                                                           |
| md / 900 px  | Application shell: sidebar versus bottom navigation, compact headers/search, My, Favorites and Album page dialogs, transfer dialog versus desktop floating window, gallery gesture-only controls. Compact tablet layouts receive the same navigation lifecycle as phones. |
| lg / 1200 px | Wide workspace: file previews use a non-modal docked inspector only from lg. Smaller previews are modal so the file list is not squeezed between a sidebar and an inspector. Workspace margins/sidebar density use the md–lg interval.                                    |
| xl / 1536 px | Available for future spacious layouts; no extra visual change is needed merely to use every breakpoint.                                                                                                                                                                   |

Use `useCompactLayout()` for shell decisions, `useBreakpointUp/Down/Between()` for component-specific space requirements, and `useReducedMotion()` for motion preferences. `useMediaQuery()` remains available for arbitrary non-layout media queries. Keep image fitting and actual viewport geometry separate from these layout decisions.

Styles use named queries such as `@media (--down-sm)`, `@media (--up-md)` and `@media (--between-md-lg)`. Vite’s small PostCSS adapter expands them from the same JS definition in development and production; CSS variables cannot parameterize media-query conditions. No generated stylesheet or MUI runtime dependency is needed. Custom 350 px exceptions were replaced with fluid category sizing.

The browser suite shares the same named thresholds. Tablet fixtures use a touch viewport, while explicit mouse-resize tests exercise both sides of sm, md, lg and xl and ensure CSS visibility agrees with runtime modal/navigation behavior.

## File sections

- File, Favorites and Album listings have no file toolbar, item totals, sidebar badges, selection totals, status pill or filter chip. Existing empty/error states, skeletons, aria-busy and error notifications communicate loading and failures. Compact Files and Favorites expose refresh in the existing three-dot menu; the Files navigation destination clears a category filter.
- Only the Home recent-file section has a small section heading: retain its 16 px / 600 text treatment without a fixed or minimum height. Empty-history directory fallback has no section heading. Collection cards have 16 px top padding and no horizontal padding. The recent heading, table header, file buttons, dividers and grid container own their 16 px horizontal inset, so row highlights span the complete card without negative margins.
- Desktop selection publishes an owner-scoped action reference to LibraryApp, which composes the real header slots for the active list. The normal options menu remains available; no substitute row is added to the list. Clean up the owner on unmount or scope changes and avoid stale actions from a covered page. In compact headers, hide the normal page title/search toggle while desktop selection actions are visible so 48 px controls still fit. Touch selection keeps its floating action panel without a numeric heading.
